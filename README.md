# Расписание ГУЗ — Telegram Mini App

Статичное приложение в стиле iOS. Хостинг — GitHub Pages (бесплатно), автообновление — GitHub Actions каждые 3 часа.

## Как это работает
1. GitHub Actions по расписанию запускает `scripts/fetch.mjs`.
2. Скрипт берёт расписание из API РУЗ (`/api/search`, `/api/schedule/group/{id}`) и сохраняет в `data/`.
3. Если что-то поменялось — коммитит и деплоит сайт на Pages.
4. Мини-апп читает `data/*.json` со своего же домена (никаких проблем с CORS).

## Запуск за 5 минут
1. Создай публичный репозиторий на GitHub и залей туда все файлы из архива (включая папку `.github`).
2. В `config.json` впиши свои группы — точно как они называются на ruz.guz.ru:
   ```json
   "groups": ["ЗК-24-1", "ЗК-24-2"]
   ```
3. **Settings → Pages → Source: GitHub Actions.**
4. **Actions → «Обновление расписания и деплой» → Run workflow.** Через минуту сайт будет на `https://<логин>.github.io/<репо>/`.
5. В [@BotFather](https://t.me/BotFather): `/newbot` → создать бота, затем `/mybots` → бот → **Bot Settings → Menu Button** → вставить ссылку на сайт. Кнопка «Расписание» появится в чате с ботом. Сервер для бота не нужен.
   - По желанию `/newapp` — получишь прямую ссылку вида `t.me/bot/app`. Можно открыть сразу нужную группу: `t.me/bot/app?startapp=<id группы>`.

## Ввод любой группы
Нажми на название группы сверху и введи, например, `З.КН.24.Б7`. Регистр и пробелы не важны. Приложение:
1. сначала ищет среди групп из `config.json`, которые выгружаются каждые 3 часа (это самый надёжный вариант);
2. параллельно ищет на сайте вуза и показывает результаты в разделе «На сайте вуза»;
3. загружает расписание и запоминает группу и последние выбранные.

Ссылка сразу на группу: `https://<логин>.github.io/<репо>/?group=З.КН.24.Б7`.

### Прокси (если поиск пишет «Сайт вуза не ответил»)
Браузер пускает мини-апп на чужой сайт, только если тот разрешает это заголовком CORS. Если ruz.guz.ru этого не делает, поднимаем свой прокси. Это бесплатно и без сервера:
1. Зарегистрируйся на [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages → Create → Worker**.
2. Вставь код из `proxy/worker.js` → **Deploy**. Получишь адрес вида `https://ruz-proxy.<имя>.workers.dev`.
3. В `index.html` найди `proxy: ''` и впиши туда этот адрес.

Бесплатный лимит — 100 000 запросов в день, для группы студентов с запасом.

Если сайт вуза блокирует и Cloudflare, поиск будет работать только по группам из `config.json`. Добавляй туда все нужные группы — их расписание всегда будет под рукой.

## Если в Actions ошибка подключения
Многие сайты вузов не пускают зарубежные IP, а серверы GitHub — за границей. Тогда сайт задеплоится с прошлыми данными, а обновлять можно так:
- запускать с компьютера в РФ: `node scripts/fetch.mjs`, затем `git add data && git commit -m upd && git push`;
- или подключить свой компьютер как self-hosted runner (Settings → Actions → Runners) и поменять `runs-on: ubuntu-latest` на `runs-on: self-hosted` в job `build`.

## Если API у сайта отличается
Открой ruz.guz.ru, DevTools (F12) → Network → выбери группу и посмотри, какой запрос возвращает пары. Поля маппятся в функции `lesson()` в `scripts/fetch.mjs` — поправить там.

## Мелочи
- GitHub отключает cron в репозитории без активности 60 дней (например, летом) — включается кнопкой в Actions.
- Выбранная группа запоминается (localStorage + Telegram CloudStorage).
- Без интернета показывается последнее загруженное расписание.
- Без данных (`data/` пустая) открывается демо-группа.
